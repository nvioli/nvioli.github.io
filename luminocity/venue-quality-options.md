## Why this needs a judgement call

**There is no ground truth.** "Is this a real venue" isn't computable from the
data we hold, so no filter here can be validated — only chosen. Three signals
are available:

| signal | reasoning | failure mode |
|---|---|---|
| **contact info** | a real business has a phone, a website, or someone has photographed it | small cafés legitimately have none of the three |
| **street number** | a POI created from a phone check-in has no address, so Foursquare has only the city | some junk entries do carry a plausible address |
| **evidence** | Foursquare description / user tips / taste tags | absent for huge numbers of real, obscure venues |

## Scoring precision/recall for real

`scripts/junk-review-sample.csv` is a blind sample for hand-scoring — 25
flagged + 25 kept venues per criterion, shuffled together, with the
`what_the_filter_did` column there to be checked *after* scoring:

- fill in `verdict_real_or_junk` for each row
- a **flagged** row judged *real* is a false positive → **precision**
- a **kept** row judged *junk* is a miss → **recall**

250 rows total, ~20 minutes. The sample is keyed off row ids, so re-running the
script reproduces exactly the same one and scores stay valid.

## Caveat: 128 venues can't be assessed yet

Rows seeded before migrations 014/015 have `NULL` website/phone/photos because
nobody ever asked Foursquare, not because Foursquare had nothing. Judging them
on "has no contact info" condemns real venues — `Nublu`, `205 Chrystie`,
`Ilegal Mezcal`, `Time Again`. They're held out of every list above and still

no price.

## Reversibility

Whatever gets picked is **not a delete**. Migration 016 adds
`locations.quality_flag` and filters flagged rows out of the `location_energy`
view, which is the only thing the app reads venues through. The rows stay in
the table, so a filter can be re-tuned and re-measured, and any check-ins
pointing at a flagged venue survive. `quality_flag` records *which* rule hid
each venue, and `--criterion=none --confirm` clears everything.

```bash
# apply a decision (migration 016 must be applied in the SQL editor first)
./scripts/run-with-secrets.sh npx ts-node --project tsconfig.scripts.json \
  scripts/flag-junk-venues.ts --criterion=combined --confirm

# settle a "but what about X?"
./scripts/run-with-secrets.sh npx ts-node --project tsconfig.scripts.json \
  scripts/flag-junk-venues.ts --explain='Old Flings'
```
